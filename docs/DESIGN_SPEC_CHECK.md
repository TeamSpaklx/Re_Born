# 디자인·구현 ↔ 기능 명세 대조

2026-10-22 기준으로, **지금 구현된 디자인(홈 Before, 하단 탭 바)과 Figma에 있는 홈 After**를 [SPEC.md](./SPEC.md)(기능 명세서)와 비교한 결과입니다.
화면 값은 [DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md), 데이터 모양은 [FRONTEND.md](./FRONTEND.md)에 있습니다.

- ✅ 맞음 / ⚠️ 명세와 다르거나 정의가 비어 있음(팀 확인 필요) / ➖ 디자인 없음

## 1. 홈 화면 요소 ↔ 명세

| 홈 요소 | 연결되는 명세 | 상태 | 비고 |
|---|---|---|---|
| "규리님, …" 인사말 | F-01 사용자 문서의 닉네임 | ✅ | 로그인 화면이 없어 지금은 샘플 값 |
| "감정 기록하기" 버튼 | F-03 감정·행동 기록 | ✅ | 누르면 기록 탭으로 이동(기록 화면은 아직 빈 화면) |

| "오늘 해볼까요?" 제안 카드 | F-08 행동 제안(고정 문구 풀, 권유 표현) | ✅ | |
| 제안 카드 오른쪽 원 | F-08 "체크리스트에 담기" 버튼 / F-04 완료 체크 | ⚠️ | 디자인은 원 하나. "담기"인지 "완료"인지 동작이 정해지지 않음 |

홈 어디에도 **관계 지수(0~100)** 는 나오지 않습니다. 명세의 핵심 값인데 관계 탭에서 보여 줄 것으로 보입니다(디자인 없음).

## 2. 하단 탭 4개 ↔ 명세

명세에는 "히스토리 탭"(F-09)만 언급되고 **탭 구조 자체는 정의되어 있지 않습니다.** 4탭(투데이/관계/기록/전체)은 Figma에서 왔고, 각 탭의 내용은 아래처럼 우리가 정한 것입니다.

| 탭 | 우리가 정한 내용 | 명세 근거 | 상태 |
|---|---|---|---|
| 투데이 | 홈 | 명세의 "홈 화면"(F-01 이후 이동, F-07 인사이트 표시) | ✅ |
| 관계 | 인물 목록 + 인물별 지수 히스토리 | F-02, F-09 ("히스토리 탭"과 이름이 다름) | ⚠️ |
| 기록 | 기록 작성·목록·상세 | F-03 | ✅ |
| 전체 | 체크리스트, 설정, 계정 | F-04, F-11 | ⚠️ 명세에 없는 추정 |

어느 탭에도 배정되지 않은 것: F-13 안전 안내 화면(위기 표현), 인사이트·제안 상세 화면, 의료 서비스가 아니라는 안내 문구 위치.

탭 바 모양은 Figma와 일치합니다(크기, 아이콘, 라벨, 색). iOS 26 이상은 시스템 네이티브 탭 바라 알약 높이(62 vs 64), 테두리·그림자 등이 달라질 수 있습니다([DESIGN_SYSTEM.md](./DESIGN_SYSTEM.md) 5.8, 7장).

## 3. 명세에는 필수인데 디자인이 없는 화면

지금은 관계·기록·전체 탭이 흰 빈 화면입니다.

| 명세 기능 | 필요한 화면 |
|---|---|
| F-01, F-11 | 로그인, 회원가입, 개인정보·AI 분석·알림 동의, 설정, 동의 철회, 기록·계정 삭제(재인증, 확인 팝업) |
| F-02 | 인물 목록, 인물 등록·수정·삭제 |
| F-03 | 기록 작성(본문·인물·감정·강도), 기록 목록, 기록 상세·수정·삭제 |
| F-04 | 체크리스트(추가, 완료 체크, 완료율) |
| F-07, F-08 | 인사이트 카드 상세, 제안 카드와 "체크리스트에 담기" |
| F-09 | 관계 히스토리 선 그래프(인물·기간 선택), 데이터 없음·오류 상태 |
| F-13 | 위기 표현 안전 안내 화면 |
| 공통 | 로딩 스켈레톤, 오류·재시도, 빈 상태 |

## 4. 명세 쪽 문제 (구현에 영향)

| 문제 | 내용 | 영향 |
|---|---|---|
| 감정 점수 범위 | F-03은 −1~+1, F-06·6.2는 −3~+3 (SPEC "변환 중 발견한 불일치" 4번) | 홈 그래프 막대 값 정의가 이 결정에 막혀 있음 |
| 용어 | "인사이트/제안/인물" vs 화면의 "관계 신호" | 문구 목록을 같은 단어로 맞추거나 연결표 필요 |
| 지원 OS | **확정:** Android + iOS 둘 다, 확인은 Windows 기기 → Android만, Mac 기기 → 둘 다 (SPEC 11장 3번, [TECH_STACK.md](./TECH_STACK.md)) | 해결됨 |

## 5. 팀에 확인할 질문 (홈 After와 샘플 데이터 확정에 필요)

1. **주간 막대 그래프의 값:** 막대 높이는 무엇의 수치입니까? (그날 기록 감정 점수의 평균 / 기록 수 / 관계 지수) — 감정 점수 범위(−1~+1 vs −3~+3)와 같이 정해야 합니다.
2. **출석 체크:** MVP 기능으로 명세에 추가합니까, 확장으로 둡니까? 추가한다면 연속 일수 규칙(자정 기준, 기기 시간대)과 알약 6개의 의미(6 미만일 때 채움 규칙)를 확정해 주세요.
3. **"최근 대화가 조금 줄었어요"** 같은 신호 문구는 어떤 계산 결과에서 나옵니까? (예: 최근 기록 수 감소, 부정 추세) — F-07의 "계산 가능한 사실만" 원칙에 맞게 정해 주세요.
4. **제안 카드의 오른쪽 원:** 누르면 "체크리스트에 담기"입니까, "완료 체크"입니까?
5. **탭 4개의 구성:** 관계(F-02+F-09), 기록(F-03), 전체(F-04+F-11)가 맞습니까? F-13과 안내 문구는 어디에 둡니까?

## 6. 구현에 미치는 영향 요약

- 홈 Before는 위 ⚠️ 항목이 있어도 샘플 데이터로 완성되어 있고, 해당 값은 `FakeHomeRepository`에서 정의합니다.
- 질문 1~4가 정해지면 `HomeSummary`의 모양이나 문구를 고쳐야 할 수 있습니다(백엔드와 맞춘 모양은 [FRONTEND.md](./FRONTEND.md)).
- 명세를 바꿀 때는 이 문서가 아니라 `docs/SPEC.md`를 PR로 수정합니다.
